# Точка одобрения ✅

## Когда стоп
- Готово ТЗ. Готов дизайн. Готова сборка к публикации.
- Перед: публикацией в Google Play / на хостинг, merge в `main`, платным сервисом, удалением файлов/веток (удаление проекта — навык `delete-project`), изменением студии (`.claude/`).

## Сначала — статус (для Telegram и табло)
В `projects/README.md` колонка «Этап» проекта → `<Этап> ✅ ждёт «да»` (например `Дизайн ✅ ждёт «да»`), коммит и **сразу push** в ветку `<slug>`. Дамиру придёт сообщение в Telegram.

## Что показать (≤10 строк)
```
✅ Нужно одобрение: <этап> — <проект>
Итог: <2–4 пункта главного>
Файл: projects/<slug>/docs/<файл>.md
Ответь: «да» — идём дальше (на Выпуске: «да» = публикую и сливаю в main), или напиши, что поменять.
```

## Правила
- Ждать ответа. Не продолжать в том же сообщении.
- «да / ок / одобряю / го» = одобрено. Правки → внести → показать снова.
- Записать решение в `projects/<slug>/docs/report.md`: `<дата> <этап>: одобрено` (или правки).
- После ответа обновить «Этап» в `projects/README.md` (следующий этап, без «ждёт «да»») и push.
- Пробный прогон с пометкой «тест» → можно записать `тест: одобрено автоматически` и идти дальше.
- Между точками одобрения — не спрашивать по мелочам.
- «да» на Выпуск или на правки офиса → сразу навык `merge-to-main` (слить PR в main самим). Без «да» в main не сливать.
- «тест: одобрено автоматически» не даёт права сливать в main.
