# Слияние в main

## Когда можно
- Дамир ответил «да» (да / ок / одобряю / го / сливай) именно на:
  - ✅ **Выпуск** проекта (`approval-gate`), или
  - показанные **правки офиса** в сессии «Офис студии».
- «да» относится к последнему показанному итогу. Были новые коммиты после «да» → показать снова и ждать новое «да».
- Нет «да» → НЕ сливать. Никогда. Ни «мелкую правку», ни «очевидное».
- Пробный прогон «тест: одобрено автоматически» — НЕ даёт права сливать.

## Как
1. Всё закоммичено в рабочую ветку (`<slug>/...` или ветка офиса).
2. Из корня репозитория:
   ```bash
   python3 scripts/merge_pr.py --title "<slug>: выпуск 1.0.0" --body "<3–5 строк: что вошло>"
   ```
   Скрипт: push → находит/создаёт PR в `main` → ждёт проверки → squash-merge.
3. Проверки упали → НЕ слито. Починить (`debugger`), закоммитить, запустить скрипт снова. Повторное «да» не нужно, если суть не менялась.
4. Отчёт 2 строки: `Слито в main: PR #N <ссылка>` или `Не слито: <причина>`.
5. Записать в `projects/<slug>/docs/report.md` (для проекта) и обновить «Этап» → «Готово» в `projects/README.md` — до слияния, в той же ветке.

## Нельзя
- Сливать без зелёных проверок, принудительно (`--force`), в обход PR, или чужую ветку.
- Пушить напрямую в `main`.
